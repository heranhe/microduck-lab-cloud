# 舵机模型与 AI 描述训练

## 舵机模型：飞特 STS3215 或官方 XL330

MicroDuck 有两种舵机。官方上游（`microduck_rl`）按 Dynamixel XL330 辨识和训练；有些机器是用飞特 STS3215（7.4V）搭的。它们不是同一种电机，训练时模拟哪一种，得到的策略就是针对哪一种。

训练时在动作行展开的设置里选择，**默认是飞特 STS3215**：

| | 飞特 STS3215（默认） | 官方 XL330 |
|---|---|---|
| 来源 | 开源 [Rhoban/bam](https://github.com/Rhoban/bam) 的 `feetech_sts3215_7_4V/m6.json` | 官方 `microduck_rl` 固定版本使用的 xl330 m6 参数 |
| 电机常数 kt | 1.275 Nm/A | 0.366 Nm/A |
| 位置增益 / PWM 上限 | 32 / 0.97 | 200 / 1.0 |
| 固件电流限制 | BAM 模型里没有 | 1.75 A（约 0.64 Nm） |
| 目标位置 | 固件按最高 5.1 rad/s 限速追赶 | 直接跟随 |
| 通信延迟 | 1–3 个物理步 | 3–6 个物理步 |
| 云端训练 | 不支持 | 支持（固定使用） |

几点需要知道：

- **参数来自上游，没有在你的机器人上测过。** 它是仿真结果，不是实机验证。上游给这个舵机提供了 m1–m6 六档摩擦模型，这里用最完整的 m6（与官方 XL330 用的同一档），没有核实它在你的舵机上的拟合质量。
- **参数取自固定提交** `31e5b97`，测试里有一项会联网核对数值是否与该文件一致。
- **云端官方任务固定使用官方 XL330**，因为官方 `mjlab` 栈只建模了它。云端训练界面会提示这一点。
- **`xml` 舵机不受影响。** 它是 XL330 的线性化近似，部分课程的“训练轮”阶段会用它；那些阶段里的舵机选择会被忽略。
- **观看训练中的小鸭子会用同一种舵机**（实验室会镜像训练进程的设置）。但训练结束后用舞台上的其他小鸭子回放、以及 `render-rollout`、`eval-*` 等脚本，用的是实验室进程自己的设置。要让它们也用飞特，启动实验室时设置 `MICRODUCK_SERVO=feetech`。
- 命令行：`MICRODUCK_SERVO=feetech|official`，或 `/teach` 请求的 `servo` 字段；不指定时，`/teach` 对 MicroDuck 默认用飞特。
- 扭矩惩罚项按各自舵机的最大扭矩归一化，所以换舵机不会让惩罚项悄悄变大或变小。

## 用 AI 描述想训练的动作

训练面板上的「✨ 用 AI 描述想训练的动作」需要你自己的 AI 服务（兼容 OpenAI 接口，或本机服务）。密钥只保存在本机 `training-plans/ai-settings.json`（权限 600），不会返回给页面。

AI 只能做两件事：

1. **选已有配方，并调整已有奖励项的权重。** 奖励项只能来自该配方自带的项或共享目录，权重 0–1000。
2. **为新动作编排关键帧**（仅 MicroDuck），再用已有的模仿训练去学。关键帧的关节角度会被限制在舵机范围内。

它**不会**写代码，也不会发明奖励项或配方。它给出的方案要通过和导入方案相同的校验；没通过时，AI 会收到原因并自动修正一次，仍然不行就把原因显示给你，什么都不会开始。方案会先显示出来，包括它改了哪些奖励项，你确认后才会保存并开始本机训练。

### 现在做不到的

- **自定义奖励代码。** 让 AI 写任意奖励函数并直接训练，需要沙箱、先用小规模试验、训练后渲染检查，还要让云端也能运行这份代码。这些没有做，所以目前奖励只能从已有的奖励项里组合。奖励设计很容易出错（比如奖励机器人观察不到的量），这类错误训练到一半才会暴露。
- **云端训练 AI 方案。** 云端只有两个官方任务，AI 方案只走本机 CPU。
- **关键帧动作能否站稳没有保证。** AI 编排的动作可能物理上做不到，模仿训练会尽力复现但可能失败；训练后请用渲染或舞台实际观察。
